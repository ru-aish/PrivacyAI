The prompt was safe. The context was not.

PrivacyAI already sanitized what a user typed. P0 closes the quieter paths that could still place real secrets in an agent model’s context: tool results, failures, files, startup instructions, resumed sessions, and race-prone local state.

The problem

One sanitizer. Five bypass routes.

A prompt-only filter protects the front door, but agent CLIs build context from many sources after that first check. Any one of them can reintroduce the original value.

T→

Tool results

A tool can discover a new email, key, identifier, or name that never appeared in the user’s prompt.

!

Failure channels

Error text and failed tool output can be inserted into the next model turn without passing through the success path.

@

Native expansion

@file, shell escapes, attachments, slash commands, resume, and fork can add local context after sanitization.

CFG

Startup context

Instructions, skills, plugins, MCP configuration, memory, and project files can silently become provider-bound context.

↻

State races

Concurrent writers, stale locks, and recycled process IDs can lose mappings or let an old process delete a new owner’s lock.

Host-aware policy

Same privacy goal. Different safe mechanics.

P0 does not pretend every CLI exposes the same lifecycle. It uses the strongest trustworthy boundary each host actually provides.

Success output is rewritten. Failed or batched private output stops the turn. Project instructions, skills, commands, agents, plugins, settings, and MCP context are preflighted.

Security contract

What P0 guarantees — and what it does not claim

The implementation distinguishes supported protection, deliberate fail-closed behavior, and one remaining transport-level limitation.

Protected

Paths with a trustworthy rewrite or preflight boundary.

  • Prompts and stable placeholders
  • Claude tool input, success output, and failure gating
  • Structured values and object keys
  • Startup files, skills, commands, agents, plugins, MCP configuration
  • Loopback-local sanitizer endpoints

Stopped fail-closed

Unsafe ambiguity does not become a silent pass-through.

  • Unresolved placeholders
  • Invalid or shape-changing sanitized JSON
  • Oversized atomic results
  • Native @file, shell, attachment, resume, and fork ingress
  • Tool paths without a reliable output replacement boundary

Remaining limitation

Codex startup serialization is inspected, but P0 does not claim universal interception of every final encrypted request.

  • Stronger coverage needs an upstream request hook
  • Alternatively, a maintained host patch
  • Or a local provider proxy at the transport boundary
